# 4장을 마치며
<!-- 슬라이드 399~400 -->

4장은 **주요 ConvNet 구조** 를 다루었다. 3장에서 AlexNet 과 VGGNet 으로 "convolution 을 쌓으면 이미지를 분류할 수 있다" 는 것을 확인했다면, 4장은 "그러면 어떻게 쌓아야 더 깊고, 더 정확하고, 더 가벼운 망이 되는가" 를 물었다. 뒤돌아보면 여섯 절은 하나의 질문을 세 번 바꾸어 물은 과정이었다. 앞의 세 절은 **층과 층을 어떻게 이을 것인가**, 다음 한 절은 **그렇게 학습된 망이 무엇을 알고 있는가**, 마지막 두 절은 **그 망을 어떻게 재활용하는가** 다.

**첫째, GoogLeNet 은 망을 넓혔다.** 하나의 큰 필터 대신 1×1 · 3×3 · 5×5 convolution 과 max pooling 을 나란히 두고 채널 방향으로 이어 붙이는 **Inception module** 이 그 답이다. 이때 파라미터가 폭발하지 않도록 각 경로 앞에 **1×1 convolution** 을 두어 채널을 줄였다. 1×1 convolution 은 Network in Network 의 MLP 를 대신하는 채널 방향 신경망이면서 동시에 bottleneck 이고, 이 한 가지 부품이 4.2 의 bottleneck block 과 4.3 의 DenseNet-B 에까지 이어진다. 마지막 FC 층을 average pooling 으로 바꾼 것과 학습 중에만 쓰는 보조 분류기도 같은 목적, 곧 "깊고 넓되 좁은" 망을 학습 가능하게 만드는 장치였다. **GoogLeNet code 분석** 에서는 네 경로 함수와 `inception_module` 클래스를 쌓아 GoogLeNet 을 직접 만들고 `torchinfo.summary` 로 층별 크기를 읽었다.

**둘째, ResNet 은 망을 깊게 했다.** 넓히는 것만으로는 안 되는 문제가 있었다. 층을 더 쌓았는데 학습 오차부터 나빠지는 degradation 이다. **Residual learning** 은 층이 $H(x)$ 를 통째로 배우는 대신 잔차 $F(x) = H(x) - x$ 만 배우게 하고, 입력을 그대로 더해 주는 **skip connection** 으로 $H(x) = F(x) + x$ 를 만든다. 이 한 줄 덕분에 weight 가 작아도 gradient 가 사라지지 않아 100층이 넘는 망이 학습된다. 깊이가 50층을 넘으면 1×1 convolution 으로 채널을 줄였다 되돌리는 **bottleneck block** 을 쓰는데, 이것이 4.1 의 1×1 convolution 이 다시 등장하는 자리다. ResNet 을 다르게 읽는 눈도 얻었다. skip 을 타거나 residual module 을 거치는 선택을 모두 펼치면 길이가 다른 여러 경로의 **ensemble** 이 되고, 그래서 layer 하나를 빼도 성능이 무너지지 않는다.

**셋째, DenseNet 은 연결을 늘렸다.** ResNet 의 skip connection 이 효과가 있었다면 연결을 더 늘리면 어떻게 될까. Dense block 의 각 층은 같은 block 안의 이전 층 출력을 모두 받되, add 가 아니라 **concatenation** 으로 받는다. 그래서 층마다 growth rate $k$ 채널이 새로 생기고, 이전 층의 feature 는 섞이지 않은 채 보존된다. 채널이 계속 늘어나는 부담은 1×1 convolution 의 bottleneck(DenseNet-B)과 transition layer 의 압축(DenseNet-C)으로 다스린다. 같은 test error 를 ResNet 보다 훨씬 적은 파라미터로 얻는다는 것이 **DenseNet 의 구조와 특성** 이 말해 주는 결론이다. 이로써 "연결" 이라는 한 축 위에 GoogLeNet(병렬) · ResNet(건너뛰어 더하기) · DenseNet(모두 이어 붙이기)이 나란히 놓인다.

**넷째, Weakly supervised learning 은 시선을 구조에서 결과로 옮겼다.** 앞의 세 절이 "어떻게 만들 것인가" 였다면 4.4 는 "만들어진 분류 모델이 무엇을 알고 있는가" 다. Class label 만으로 학습한 CNN 도, FC layer 를 global average pooling 으로 바꾸면 이미 갖고 있던 localization 정보가 드러난다. 출력층의 가중치를 마지막 conv feature map 에 투영한 것이 Class Activation Map 이고, 이것이 값비싼 bounding box 없이 **scene & object detection** 을 하고, 행동·사건처럼 여러 요소로 규정되는 개념의 근거 영역을 찾는 **concept localization** 을 하고, "텍스트가 있다/없다" 만으로 간판의 글자를 찾는 **text detection** 까지 해낸다는 것을 보았다. 4.1 의 average pooling 이 여기서 다시 뜻을 얻는다.

**다섯째, Transfer learning 실습은 학습된 망을 재활용하는 법을 손에 익혔다.** ImageNet 으로 학습된 **pre-trained model(VGG16, Inception-v3)** 을 불러와 필요 없는 부분을 떼어 내고, 앞쪽 convolution 층은 **layer freezing** 으로 얼려 둔 채, 내 class 수에 맞는 layer 를 **layer adding** 으로 붙이고, 내 데이터로 **fine tuning** 했다. 같은 절차를 CIFAR10 · custom dataset · 복잡한 Inception 구조에 세 번 적용하면서, freeze 경계를 index 로 잡는 법과 이름(`named_children()`)으로 잡는 법, 학습 모드 출력의 `.logits` 를 다루는 법을 배웠다.

**여섯째, CAM 실습은 4.4 의 개념을 코드로 만들었다.** 다만 VGG16 에는 FC layer 가 있어 출력층 가중치를 그대로 읽을 수 없으므로, class 점수를 feature map 으로 편미분한 gradient 를 관련성으로 쓰는 **Grad-CAM** 을 구현했다. forward hook 과 backward hook 으로 feature map 과 gradient 를 같은 shape 으로 받아 내고, 가중합 → ReLU → 해상도 확대 → 정규화 → color mapping → blending 의 순서로 heat map 을 원본에 겹쳤다. 4.5 에서 익힌 사전학습 모델 불러오기가 그대로 쓰였고, 4.4 의 "분류 모델은 위치를 안다" 가 눈으로 확인되었다.

**스스로 점검할 것** — 다음을 설명할 수 있으면 4장은 끝났다.

- Inception module 의 구조와, 1×1 convolution 이 파라미터를 줄이는 원리. GoogLeNet 코드에서 네 경로가 어떻게 합쳐지는가.
- Residual learning(skip connection)이 degradation 을 푸는 이유, bottleneck block 의 구성, ResNet 을 ensemble 로 보는 해석.
- DenseNet 의 Dense block 이 ResNet 과 다른 점(concatenation, growth rate)과 DenseNet-BC 의 구성.
- Class label 만으로 scene & object detection · concept localization · text detection 이 가능한 이유(global average pooling 과 CAM).
- Pre-trained VGG16 · Inception-v3 를 활용할 때 layer freezing · layer adding · fine tuning 을 어느 순서로, 어느 경계에서 하는가.
- Grad-CAM 구현의 핵심 — hook 으로 feature map 과 gradient 를 얻어 CAM 을 만드는 단계.

다음 장에서는 이미지에서 순서가 있는 데이터로 옮겨 간다. 5장 Recurrent Neural Network 는 RNN cell 의 구조와 RNN 모델의 구조를 먼저 정리한 뒤, 시계열 · 문자(Char-RNN) · MNIST 를 RNN 으로 다루는 실습을 거쳐 필기 생성(handwriting generation)까지 나아간다. 4장에서 익힌 "구조를 읽고, PyTorch 로 만들고, `summary` 로 확인하는" 습관은 그대로 이어진다.
